# ML Server Environment Variables

## JWT Configuration (must match the Express.js backend)

This setting defines the secret key used for signing JSON Web Tokens (JWTs) for authentication. It must be the same as the `JWT_SECRET` used in the Express.js backend to ensure that tokens generated by the backend can be verified by the ML server. Change this to a secure value before deploying to production.

There is no default value, so you must set it before running the ML server.

```env
JWT_SECRET=your-super-secret-jwt-key-here-change-in-production
```

## Django Configuration

`DEBUG` is set to `False` by default, and `DJANGO_SECRET_KEY` has no default value, so you must set it to a secure value before deploying to production.

- NOTE: The `DEBUG` setting should be set to `False` in production environments for security reasons. The `DJANGO_SECRET_KEY` should be a unique and secure value that is kept secret in production.

```env
DEBUG=False
DJANGO_SECRET_KEY=your-django-secret-key-here
```

## CORS Configuration

This setting defines which origins are allowed to make cross-origin requests to the ML server. You can specify multiple origins separated by commas. There is no default value, so you must set this variable to enable CORS for your Express.js and React frontend applications.

```env
CORS_ALLOWED_ORIGINS=http://localhost:5000,http://127.0.0.1:5000,http://0.0.0.0:5000
```

## Allowed Hosts

This setting defines which host/domain names the ML server can serve. You can specify multiple hosts separated by commas. There is no default value, so you must set this variable to allow the server to respond to requests from your Express.js and React frontend applications.

```env
ALLOWED_HOSTS=localhost,127.0.0.1,0.0.0.0
```

## Static Files Configuration

This setting defines the URL path for serving static files (CSS, JavaScript, images). Change it if you want to serve static files from a different URL path.

The default is set to `static/`, which means static files will be accessible at `http://your-domain.com/static/`.

```env
STATIC_URL=static/
```

## Logging Level

You can control the verbosity of logging output by setting the `LOG_LEVEL`. Common values are `DEBUG`, `INFO`, `WARNING`, `ERROR`, and `CRITICAL`. For production environments, it's recommended to set this to `INFO` or higher to reduce log noise. The default is `INFO`.

```env
LOG_LEVEL=INFO
```

## Databsase Engine Selection

The `DB_ENGINE` variable allows you to select which database backend to use. Supported values are `postgresql`, `mysql`, and `sqlite`. If not set, it defaults to `sqlite`.

- NOTE: For production environments, it's recommended to use PostgreSQL or MySQL instead of SQLite.

```env
DB_ENGINE=sqlite  # Change to postgresql or mysql as needed
```

## Database Configuration (PostgreSQL)

```env
DB_ENGINE=postgresql
DB_NAME=ml_server_db
DB_USER=postgres
DB_PASSWORD=1234
DB_HOST=localhost
DB_PORT=5432
```

## Database Configuration (MySQL)

```env
DB_ENGINE=mysql
DB_NAME=ml_server_db
DB_USER=root
DB_PASSWORD=1234
DB_HOST=localhost
DB_PORT=3306
```

## Database Configuration (SQLite - default if DB_ENGINE is not set)

- NOTE 1: For SQLite, the database file will be created at the specified path. Change as needed.
- NOTE 2: Do not use SQLite in production environments. It is only suitable for development and testing.

```env
DB_ENGINE=sqlite
DATABASE_PATH=/path/to/your/sqlite/db.sqlite3
```
